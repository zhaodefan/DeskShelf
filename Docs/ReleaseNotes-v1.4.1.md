## 问题

Snipaste 截完图按 `Ctrl+V` 粘进面板，卡片位置正确、尺寸正确、也有文件大小，但**显示为空**（全透明）。
双击用看图软件打开，同样是空白。

## 根因

不是 DeskShelf 读错了图，是**这张图在剪贴板里就已经"没有透明度信息"了**。

实测 Snipaste 放进剪贴板的是：

| 剪贴板格式 | 实际内容 |
| --- | --- |
| `CF_DIB`（`DeviceIndependentBitmap`） | `biSize=40`，**24bpp**，`BI_RGB` —— 没有 alpha 通道 |
| `CF_DIBV5`（`Format17`） | `biSize=124`，**24bpp**，`alphaMask=0x00000000` |
| `CF_BITMAP` | 同上 |

关键点：**Snipaste 根本不提供 PNG 自定义格式**（Chrome、QQ 等通常会给 `PNG` 格式，那份 alpha 是对的）。
而 WPF 把 24bpp 的 DIB 读进来时会统一包装成 `InteropBitmap`，像素格式 `Bgra32` ——
多出来的那个 alpha 通道**全是 0**。

DeskShelf 之前把这个位图原样编码成 PNG，于是得到一张 **100% 透明**的 PNG：
RGB 数据完好，但每个像素的 alpha 都是 0，任何看图软件都显示为空白。

## 修复

新增 `src/DeskShelf.Infrastructure/Imaging/ImageAlphaSanitizer.cs`：

- **只在"整幅图 alpha 全为 0"时**才动手 —— 把 alpha 全部置 255，RGB 原样保留。
- 真正带透明区域的图（比如从浏览器复制的透明 PNG）alpha 不可能全为 0，**不会被误伤**。
- 粘贴路径（`DataObjectReader.TryReadImagePng`）在编码前调用它。

## 旧图会自动救回

以前粘进去的空白图片不用手动重粘 —— 升级后第一次启动会自动扫描并修复 `%APPDATA%\DeskShelf\images\`，
同时**重建缩略图**（旧缩略图也是全透明的）。

修复前会写标记文件 `.image-repair-v1`，保证只扫一次；修复失败时不写标记，下次启动自动重试，且**绝不影响启动**。

## 顺带

- `ImageFileStore` 改为同时注册具体类型（供启动时一次性修复调用），接口注册指向同一实例，行为不变。
- 新增 5 个剪贴板/图片诊断小工具在 `tools/`：`ClipProbe.cs`（枚举剪贴板格式）、`DibProbe.cs`（解析 DIB 头与 alpha 分布）、
  `PngAlphaProbe.cs`（统计 PNG alpha）、`PngRgbProbe.cs`（RGB 峰值与 alpha 修复另存）、`ClipImageRepro.cs`（复现产品读取路径）。
  排查此类问题可直接 `Add-Type -Path` 加载。

## 已知限制

- **粘贴纯透明图片**（整幅 alpha 全 0 且本来就想透明）：会被当作"没有 alpha 信息"修复成不透明。
  这种图放进置物架本来也没有意义，故不单独处理。
- 若截图工具给的是**预乘 alpha 且全 0**的位图（`Pbgra32`），RGB 在预乘时已被清零、无法还原，修复结果为纯黑。
  Snipaste / Windows 截图 / QQ / 微信均不属于此类（实测最高值为 `alpha 0~0` 但 RGB 完好）。
- **把资源管理器窗口（标题栏 / 地址栏）直接拖进面板保存该目录**：做不到，原因见 `Docs/Development-Plan.md` §13。
- 在线更新需要能访问 GitHub；无法访问时请到发布页手动下载。
