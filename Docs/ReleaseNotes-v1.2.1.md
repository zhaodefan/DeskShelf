## 本版修复

### 1. 新建文本输入后卡片预览空白

**现象**：点「+ 新建文本」输入文字、提交后，卡片上什么都不显示，必须双击进入编辑才看得到内容。

**原因**：卡片预览绑定到 `UnitViewModel.Text`，而这个属性原本是**只读的**（`public string? Text { get; }`）。
提交编辑时只更新了领域对象，没有通知界面；而列表同步逻辑 `SyncUnits` 为了保持选中状态与滚动位置，
会**复用**已有的 ViewModel（不重建），所以界面永远显示创建时的空值。

**修复**：`Text` 改为可通知属性，`CommitText` 提交后同步一次显示值：

- 正常提交 → 卡片立即显示新文本
- 领域层判定「内容无变化」时也会同步（保证卡片与落盘内容一致）
- 显示的是**归一化后**的文本（首尾空白被裁剪），用户看到的即实际保存的

新增 3 个回归测试锁住这个行为（含"无变化也要同步"与"显示归一化文本"两种边界）。

### 2. 深色主题下文本光标看不清

**现象**：深色主题里编辑文本时，光标几乎是黑色的，落在深色背景上几乎看不见。

**原因**：编辑框的 `TextBox` 没有设置 `CaretBrush`，WPF 会沿用**系统默认**光标色（偏黑），
它不会跟随应用主题。

**修复**：新增 `Brush.Caret` / `Brush.Selection` 主题令牌，颜色**引用 `Color.Text.Primary`**
（深色 `#FFE6E9ED` / 浅色 `#FF1F2328`），所以光标色自动与应用文字色保持一致、随主题切换。
同时给设置窗口的输入框（unit 上限、GitHub 令牌）补齐了同样的光标与选区色。

> 验证方式：临时把光标改成纯洋红并截屏，捕获到 16 个纯 `RGB(255,0,255)` 像素、集中在单一 X 轴、
> 纵向 16px —— 确认 `CaretBrush` 绑定在运行时确实生效，再恢复为对比色。

## 完整功能

- **置顶小面板**：默认在鼠标所在屏右下角，位置尺寸自动记忆，可拖动可缩放
- **三类 unit**：文本（行内编辑 / 复制）、图片（缩略图 / 看图程序打开）、文件夹（资源管理器打开）
- **新建文本**：标题栏下方「+ 新建文本」，新建空白 unit 并立刻可输入
- **拖拽落盘**：文件夹 / 图片 / 普通文件都能拖入；拖普通文件会存它所在的目录；`.lnk` 解析真实目标
- **多选与撤销**：`Ctrl+点击` 多选、`Shift+点击` 区间；删除后 5 秒内可撤销
- **全局热键** `Alt+X`（可改，带占用检测）
- **托盘常驻** + **明暗主题**（跟随系统 / 浅色 / 深色）
- **应用内在线更新**：设置 → 更新 → 检查更新 → 下载并安装，自动完成升级并重启
- **数据安全**：原子写入 + 防抖保存；数据文件损坏时自动备份并以空面板启动
- **安装/卸载**：per-user 免管理员；卸载默认保留用户数据

## 数据位置

```
%APPDATA%\DeskShelf\
├─ shelf.json     面板内容      ├─ settings.json  设置
├─ images\        图片原件与缩略图
├─ updates\       下载的安装包    ├─ logs\  运行日志      └─ backup\  损坏数据自动备份
```

## 已知限制

- **把资源管理器窗口（标题栏 / 地址栏）直接拖进面板保存该目录**：做不到。拖放由"拖源"主导，
  标题栏属于非客户区，系统按"移动窗口"处理而非数据传输。请从列表里拖文件夹，或拖目录里的任意文件（会存其所在目录）。
- 在线更新需要能访问 GitHub；无法访问时请到发布页手动下载。
- `Alt+X` 属菜单助记符空间，个别程序前台时可能被其菜单占用；可在设置里换成 `Ctrl+Shift+...`。
