> **修复应用内更新失败**（下载完成后提示「安装程序返回退出码 1」）。中文名：**桌面置物架**　英文项目名：**DeskShelf**

## 本版修复

### 应用内更新提示「安装程序返回退出码 1」

**现象**：设置 → 更新 里下载完安装包后，报「安装程序返回退出码 1，升级可能未完成」，实际没有升级。

**根因**：安装包设置了 `AppMutex`（用于在安装/卸载时自动关闭正在运行的程序），
而更新流程是**由程序自己**启动安装包 —— 此时程序必然还在运行。安装包因此弹窗要求先关闭程序：

```
安装程序检测到 DeskShelf 当前正在运行。
请先关闭正在运行的程序，然后点击"确定"继续，或点击"取消"退出。
```

而这个弹窗被更新器的 `/SUPPRESSMSGBOXES` 抑制了，**被抑制的对话框会自动选择「取消」**，
于是安装立即中止，返回退出码 1。

> 试过 `/FORCECLOSEAPPLICATIONS`，无效 —— Inno Setup 的 AppMutex 检查发生在应用关闭机制之前。

**修复**：改为 **helper 进程接管**。点「下载并安装」后：

1. 下载并校验安装包（这一层原本就正常）
2. 启动一个**独立的 helper 进程**（批处理，完全脱离主程序）
3. 主程序立即退出
4. helper 检测到主程序已消失 → 以 `/VERYSILENT` 静默安装 → **自动重启新版本**

helper 的日志写在 `%TEMP%\DeskShelf-update-<时间戳>.log`，升级出问题可直接查看。

**顺带修掉的小问题**：下载完成时的进度回调会异步覆盖掉后续的「准备安装」提示，
导致界面卡在「正在下载安装包… 100%」。现在进度收尾由调用方统一负责。

### 验证方式（端到端实测）

| 步骤 | 结果 |
| --- | --- |
| 1.2.0 运行中，helper 启动 | 日志记录 `wait for pid …`，helper 等待中 |
| 主程序退出 | helper 检测到进程消失，进入安装 |
| 静默安装 | 退出码 0，文件版本变为 **1.2.1** |
| 自动重启 | 新版本进程被拉起（StartTime 相符） |
| 卸载项 | 显示 **1.2.1** |

新增 4 个单元测试守护 helper 脚本的关键约定：等待步骤必须在安装之前、安装必须在重启之前、
静默参数不得依赖 `FORCECLOSEAPPLICATIONS`。

## 完整功能

- **置顶小面板**：默认在鼠标所在屏右下角，位置尺寸自动记忆，可拖动可缩放
- **三类 unit**：文本（行内编辑 / 复制）、图片（缩略图 / 看图程序打开）、文件夹（资源管理器打开）
- **新建文本**：标题栏下方「+ 新建文本」，新建空白 unit 并立刻可输入
- **拖拽落盘**：文件夹 / 图片 / 普通文件都能拖入；拖普通文件会存它所在的目录；`.lnk` 解析真实目标
- **多选与撤销**：`Ctrl+点击` 多选、`Shift+点击` 区间；删除后 5 秒内可撤销
- **全局热键** `Alt+X`（可改，带占用检测）
- **托盘常驻** + **明暗主题**（跟随系统 / 浅色 / 深色）
- **应用内在线更新**：设置 → 更新 → 检查更新 → 下载并安装，自动完成升级并重启
- **数据安全**：原子写入 + 防抖保存；数据文件损坏时自动备份并以空面板启动

## 数据位置

```
%APPDATA%\DeskShelf\
├─ shelf.json     面板内容      ├─ settings.json  设置
├─ images\        图片原件与缩略图
├─ updates\       下载的安装包与 helper 脚本
├─ logs\          运行日志      └─ backup\  损坏数据自动备份
```

## 已知限制

- **把资源管理器窗口（标题栏 / 地址栏）直接拖进面板保存该目录**：做不到。拖放由"拖源"主导，
  标题栏属于非客户区，系统按"移动窗口"处理而非数据传输。请从列表里拖文件夹，或拖目录里的任意文件。
- 在线更新需要能访问 GitHub；无法访问时请到发布页手动下载。
- `Alt+X` 属菜单助记符空间，个别程序前台时可能被其菜单占用；可在设置里换成 `Ctrl+Shift+...`。
