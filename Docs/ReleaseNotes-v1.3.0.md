## 新功能：文件 unit

### 怎么用

把**任意文件**从资源管理器拖进面板即可：

- 卡片显示「文档图标 + 文件名 + 完整路径」
- **双击用系统默认程序打开**（`.pdf` → 阅读器、`.docx` → Word、`.txt` → 记事本……由文件关联决定）
- 右键可「打开」或「在资源管理器中显示」
- 选中后 `Ctrl+C` 以**文件形式**复制，可直接粘贴到资源管理器

图片文件仍走图片 unit（可看缩略图、可复制图片本身），文件夹仍走文件夹 unit。

### 一处行为变更（请留意）

**以前**：拖入普通文件会存成「它所在的目录」。
**现在**：存文件本身。

那是因为在文件 unit 出现之前，没有更好的处理方式。现在：
- 想存目录 → 直接拖文件夹
- 想存文件 → 直接拖文件

## 同时完成的待办 B1：升级后自动清理安装包

之前每次在线升级会把约 **64 MB** 的安装包留在 `%APPDATA%\DeskShelf\updates`，多次升级会累积几百 MB。现在的规则：

| 时机 | 行为 |
| --- | --- |
| 安装**成功** | helper 进程删除安装包 |
| 安装**失败** | 保留安装包，便于重试与排查 |
| 每次启动 | 清理上次残留的 helper 脚本与未完成的 `.part` 文件（**不删**已下载的安装包） |

## 顺带修掉的问题

- **更新进度回调的竞态**：下载结束后仍在线程池队列里的进度回调，会覆盖「下载完成 / 失败」这类收尾提示（表现为状态文字停在「正在下载 100%」）。已加下载期开关把它挡掉。这是测试里偶发失败暴露出来的真实竞态。

## 完整功能

| 类型 | 怎么进来 | 双击 | 复制 |
| --- | --- | --- | --- |
| 文本 | `Ctrl+V` 粘贴 / 「+ 新建文本」 | 行内编辑 | 复制文本 |
| 图片 | 粘贴或拖入图片文件 | 看图程序打开 | 复制图片 |
| 文件夹 | 拖入文件夹 | 资源管理器打开 | 不支持 |
| **文件** | **拖入任意文件** | **默认程序打开** | **复制为文件** |

其他：置顶小面板（位置尺寸记忆、可拖动缩放）、多选与 5 秒撤销、全局热键 `Alt+X`、托盘常驻、明暗主题、应用内在线更新、原子写入 + 防抖保存 + 损坏自动备份、per-user 免管理员安装。

## 数据位置

```
%APPDATA%\DeskShelf\
├─ shelf.json     面板内容      ├─ settings.json  设置
├─ images\        图片原件与缩略图
├─ updates\       升级用的安装包与脚本
├─ logs\          运行日志      └─ backup\  损坏数据自动备份
```

文件 unit **只保存路径**，不复制文件本体。原文件被移动或删除后，该 unit 的路径会失效（打开时提示无法打开），不会自动清理。

## 已知限制

- **把资源管理器窗口（标题栏 / 地址栏）直接拖进面板保存该目录**：做不到。拖放由"拖源"主导，
  标题栏属于非客户区，系统按"移动窗口"处理而非数据传输。请从列表里拖文件夹或文件。
- 在线更新需要能访问 GitHub；无法访问时请到发布页手动下载。
- `Alt+X` 属菜单助记符空间，个别程序前台时可能被其菜单占用；可在设置里换成 `Ctrl+Shift+...`。
