## 修复：快捷方式「点了没反应」

### 现象

程序已经在后台运行（面板已收起，或托盘图标在任务栏折叠区里找不到）时，
双击桌面 / 开始菜单快捷方式，**面板不出现**，看起来就像"打不开"。

### 根因

单实例保护确实生效了——它阻止了第二个进程，但**处理方式错了**：
旧实现只弹一个「桌面置物架已经在运行（请查看任务栏通知区域）」的提示框就退出。
用户点快捷方式的真实意图是"把面板叫出来"，提示框只在说"我没启动"，却没有把已有面板显示出来。
把提示框关掉后什么都没发生，于是就成了"打不开"。

### 修复

改为**唤醒已有实例**：

1. 首实例启动时创建一个具名事件（`Global\DeskShelf.ShowPanel`）并监听
2. 后启动的实例发一个唤醒信号，然后**静默退出**（仍然是单实例，不会多开）
3. 首实例收到信号 → 把面板显示出来并置前

细节：

- 用**自动重置事件**：如果唤醒请求在首实例还没开始监听时就到了，事件会保持有信号状态，
  等监听注册后立刻消费 —— "刚启动又点一次"这种时序不会丢请求
- 唤醒通道不可用时（权限异常等）才退回原来的提示框，至少让用户知道程序在跑
- 托盘的"再次启动"与"点快捷方式"行为一致

### 验证

| 步骤 | 结果 |
| --- | --- |
| 面板收起（可见窗口 0） | ✅ |
| 启动第二个实例 | 第二个进程立即退出，**无多开、无提示框** |
| 原实例面板 | ✅ **自动出现**（日志：`收到再次启动请求，显示面板`） |

新增 5 个单元测试守护该通道，其中专门覆盖「信号先于监听到达也不能丢」这一时序。

## 小提示：托盘图标可能被折叠

Windows 10/11 默认把新程序的托盘图标放进折叠区（点任务栏 `^` 才看到）。
如果找不到托盘图标，可以：

- 按 `Alt+X` 呼出面板
- 在「任务栏设置 → 选择哪些图标显示在任务栏上」里把桌面置物架设为**显示**
- 或者直接把它的图标拖到任务栏可见区域
